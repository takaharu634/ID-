# データ更新

## 使い方

管理者画面でTrackMan CSVを選び「検証して反映」。日付から2025秋・2026春・2026秋を判定し、既存シーズンへ追加する。追加される球の異常の可能性がある値・未登録名は確認待ちにする。以前から含まれる測定欠損は別に報告し、正常な追加を毎回止めない。同じPitchUIDで内容が一致すれば重複除去、不一致は停止。複数シーズン、必須構造列の欠落、不正な数値、同じ試合・球番号の異なるIDも停止する。

1〜2月・未対応年度は自動判定せず停止。CSVはUTF-8、最大30MB、統合後25,000球まで。現時点では新しい年度の表示追加はコード側の対応が必要。

## 保存・復元

管理画面の「バックアップ・復元」から対象シーズンの保存版を選べる。戻す前の版も残る。各版のCSVをダウンロードできる。初回更新では同梱版も退避する。

R2に入力CSV、統合CSV、集計JSON、回転JSON、検証レポートを別々の不変オブジェクトとして保存する。書込時にSHA-256を照合し、切替時にも保存チェックサムを確認する。検証後1時間以内、かつ保存先の世代が変わっていない場合だけ公開ポインタを条件付き更新する。同時更新は片方が失敗し、再検証が必要。途中保存物があっても公開中のポインタは変わらない。

CSV処理は管理画面のWeb Workerで実行し、サーバーに重いCSV解析を置かない。検証時は画面を開いたまま待つ。計算用メモリ不足が起きる端末ではPCを使うか試合ごとに分ける。保存API、履歴、元CSV取得は既存の管理者認証を必須とする。認証経路・管理者の許可リスト・公開範囲は維持。

古い `datasets/current.*` は移行前の読取用。v2の更新を始めたシーズンはv2のみを参照する。D1旧履歴は変更しない。古い管理画面や外部処理からlegacyキーへ書かないこと。

## アプリ自体を過去版へ戻す

データの復元とソースの復元は別操作。アプリはSitesの保存済みバージョンを再公開する。今回の作業開始時の公開版は116。GitHubでは変更を打ち消すcommit（git revert）を作り、CI成功後に同じソース状態から再公開する。履歴を強制上書きしない。認証設定・R2のデータポインタはコードの巻き戻しだけでは戻らない。

旧アプリ版はv2データを理解しない。データ更新後に旧アプリへ戻す場合、静的同梱データに戻って見えるため、必要な現行CSVを先に保存し、v2対応版への復帰か互換修正を行う。

## 検証

`npm run test:import`：CSV構造、重複、競合、季節、球種の境界、バックアップ失敗、復元、同時更新、名寄せ。

`npm test`：既存回帰テスト、型検査、公開用ビルド、レンダリング、Workers実行環境でのAPI認可と実データ追加・復元。

実際のChatGPTアカウント認証の往復は検証環境では再現できないため、管理者の実アカウントでのサインイン完了とは区別する。
