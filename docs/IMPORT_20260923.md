# データ更新（2026年9月28日改訂）

## 使い方

管理者画面でTrackMan CSVを選び「検証して反映」。日付から年度・春秋を判定し、新しいシーズンも自動登録する。複数ファイルをまとめて選択でき、シーズンごとに検証・保存する。1ファイル内の複数シーズン混在、必須構造列の欠落、不正な数値、同じ試合・球番号の異なるIDは停止する。同じPitchUIDで内容が一致すれば重複除去、不一致は停止する。

追加分の測定欠損や異常値は確認待ちにする。以前から含まれる測定欠損は別に報告し、正常な追加を毎回止めない。漢字未登録選手は元の名前で表示し、それだけを理由に停止しない。警告付きの新年度は確認後に公開される。複数シーズンの一部で反映に失敗しても、反映済みの版と残りの確認・反映待ちを区別して表示する。

CSVはUTF-8。3〜7月を春、8〜12月を秋とし、1〜2月は判定できないため停止する。年度を列挙するコードや30MB・25,000球の固定制限はない。処理できる量は端末のメモリに依存するため、大量データはPCで試合別CSVとして追加する。測定項目・競技ルールの変更は別途ソフトウェア対応が必要。

## 保存・復元

管理画面の「バックアップ・復元」から対象シーズンの保存版を選べる。戻す前の版も残る。各版のCSVをダウンロードできる。初回更新では同梱版も退避する。

R2に入力原本、統合CSV、集計JSON、回転JSON、検証レポートを保存版として結び付ける。大きな内容は圧縮・分割し、変更のないブロックは再利用する。書込時と公開前にSHA-256を照合する。検証後1時間以内、かつ保存先の世代が変わっていない場合だけ公開ポインタを条件付き更新する。同時更新は片方が失敗し、再検証が必要。途中保存物があっても公開中のポインタは変わらない。40件を超える履歴も別索引に保存し、画面の「以前の保存版」から参照できる。

別タブへの反映通知と、画面への復帰・オンライン復帰時の更新確認を行う。比較、回転、バレルも新しい保存版を取得する。保存成功後の画面再取得だけが失敗した場合は、その旨を表示するため、同じCSVを慌てて追加し直す必要はない。

CSV処理は管理画面のWeb Workerで実行し、サーバーに重いCSV解析を置かない。検証時は画面を開いたまま待つ。計算用メモリ不足が起きる端末ではPCを使うか試合ごとに分ける。保存API、履歴、元CSV取得は既存の管理者認証を必須とする。認証経路・管理者の許可リスト・公開範囲は維持。

古い `datasets/current.*` は移行前の読取用。v2の更新を始めたシーズンはv2のみを参照する。D1旧履歴は変更しない。古い管理画面や外部処理からlegacyキーへ書かないこと。

## アプリ自体を過去版へ戻す

データの復元とソースの復元は別操作。アプリはSitesの保存済みバージョンを再公開する。GitHubでは変更を打ち消すcommit（git revert）を作り、CI成功後に同じソース状態から再公開する。履歴を強制上書きしない。認証設定・R2のデータポインタはコードの巻き戻しだけでは戻らない。

旧アプリ版はv2データを理解しない。データ更新後に旧アプリへ戻す場合、静的同梱データに戻って見えるため、必要な現行CSVを先に保存し、v2対応版への復帰か互換修正を行う。

## 検証

`npm run test:import`：CSV構造、重複、競合、季節、球種の境界、バックアップ失敗、復元、同時更新、名寄せ。

`npm test`：既存回帰テスト、型検査、公開用ビルド、レンダリング、Workers実行環境でのAPI認可と実データ追加・復元。

実際のChatGPTアカウント認証の往復は検証環境では再現できないため、管理者の実アカウントでのサインイン完了とは区別する。
