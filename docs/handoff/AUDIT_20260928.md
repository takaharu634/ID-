# ID東都 追加点検（2026-09-28）

対象は公開v136（66b31c2cd0e15da7f6dd2f1b521c733f755775b1）。GitHub mainは1c33252a4e9167ea68239e467333bb53d5429708で、同じソースツリーを確認した。v135の育成指標と、選択統合済みPR #1の長期保存基盤を保持する。Google Driveの初回接続は今回の対象外。

## 見つけて修正した点

1. 同じシーズンの更新後、比較・回転画面が以前のデータを保持していた。カタログの保存版が変わる前に共有キャッシュを無効化し、各画面で取得し直す。変更のないカタログでは不要な取得をせず、取得失敗は次の確認時に再試行する。DELTAの選手・条件を保持する。
2. バレル画面で漢字名未登録の選手を除外していた。元の選手IDと大学で分離して表示し、新年度に青山学院大学がない場合も存在する大学を選べる。
3. 横位置の欠損が数値0へ変換され、中央コースに加算されていた。欠損は除外し、実測0は残す。
4. 警告付き新年度のCSVを確認前に表示しようとしてエラーになっていた。確定したシーズンだけを取得する。複数シーズンの途中失敗でも、反映済みと未反映の検証結果を保持する。
5. 保存後の再取得・別タブ通知の失敗を「反映失敗」と扱っていた。保存成功と表示更新失敗を区別し、通知非対応でも保存を成功扱いにする。照合が進まない応答は際限なく繰り返さない。
6. 大きな配列をMath.max/minやpushの引数へ展開し、16万球で呼出上限に達していた。反復処理へ変更し、指標定義と欠損処理を維持する。
7. 公開APIで件数・最低球数の省略が1として扱われていた。選手50件、ランキング20件・最低20球など、既定値を適用する。
8. 入力原本CSVのContent-Typeをtext/csvへ修正する。管理者認証は維持する。
9. 端末のキャッシュ利用拒否・容量不足により正常なページ・JS・データ応答が失敗扱いになっていた。通信結果を表示し、アプリキャッシュも128件へ制限する。

過去の更新マニュアルの年度制限・25,000球制限の説明も現行仕様へ更新。試験で作られる一時ファイルを今後のソース保存から除外する。既存の追跡済みファイルは削除しない。

## 運用上の残り

- DriveのGoogle初回認証と実通知の往復確認は未実施。接続待ちのままである。
- 毎回の更新前後の自動バックアップはR2の同一保存領域内。別事業者・別アカウントへの自動複製は実装していない。GitHubにはアプリと同梱データを保存するが、管理画面で将来追加したR2の原本を自動コミットする仕組みではない。独立保管には既存の原本ダウンロード・検証付きアーカイブCLIを使える。
- オフライン保持は取得済みの同梱データが対象。R2へだけ追加した新年度の完全なオフライン利用は保証しない。
- 認証付き追加・復元は隔離Workerで検証する。本番の管理者ログインから実CSVを追加する往復は、本番データを変えるため今回の点検には含めない。
- 固定の年度・球数制限は廃止済みだが、1シーズンの解析は端末メモリを使用する。無制限の容量や外部サービスの稼働を保証するものではない。
