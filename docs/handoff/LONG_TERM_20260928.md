## 日常の追加

- 管理画面へUTF-8 TrackMan CSVを複数選択する。日付から年度・春秋を判定し、シーズンを自動登録する。年度の列挙や25,000球制限はない。
- 既存PitchUIDと内容が一致する行は追加しない。同じIDの改変、同じ試合/球番号の矛盾、混在シーズン、必須列不足、不正数値は止める。測定欠損などは既存分と追加分を区別し、追加分の警告には確認を求める。
- 新しい選手は元の名前で表示する。漢字名が未登録という理由だけでは追加を止めず、推測で漢字へ変換しない。指標や測定列の仕様変更は通常のソフトウェア変更として扱う。
- CSV・集計JSON・回転JSON・検証レポート・入力原本を同じ保存版に結び付ける。複数CSVの個々の入力原本はsources JSON内に元の文字列のまま保持する。
- 開いている別タブには反映を通知する。再表示、フォーカス、オンライン復帰時にも保存版の更新を確認する。定期的なAI実行やCSV巡回は追加しない。

## 分割保存・バックアップ・復元

- R2の既存v2 headと旧保存版を読み続け、新しい大きなオブジェクトは圧縮した小さなv3ブロックと索引で保存する。集計JSONは試合境界/100球単位、その他は約128K文字単位。SHA-256をキーにし、同じブロックは再利用する。
- 保存時は読み戻し、圧縮の復元、ハッシュを照合する。公開前のサーバー確認は最大80参照ずつ継続し、完了するまで公開headを変更しない。競合時はETagで先行更新を守る。
- 初回更新前の同梱データも保存する。毎回の公開切り替え前に旧headを保存し、履歴40件を超えた分は別オブジェクトへ退避する。削除はしない。履歴画面は40件ずつ取得し、古い版も再検証して復元できる。
- 容量画面は200件単位で実測する。表示値はその時点で確認したR2領域の値であり、契約上限や請求額ではない。
- ブラウザーは必要なシーズンだけを読み、共有メモリーキャッシュは最大6データ、端末のオフラインデータは最大12ファイルを保持する。端末容量不足でも正常なネットワーク応答を隠さない。
- ソース同梱の7個の大きなJSONは、SHA-256付き4MiBブロックをgzip圧縮して`data/bundled/`へ保存する。`prepare-data`が完全なJSONを復元して従来どおり配信する。ローカルの明示的な変更は保持し、同コマンドが圧縮元へ反映する。GitHubにも同じブロックを保存し、完全なソースから再ビルドできる。
- R2の履歴は同じ保存領域内のバックアップである。R2契約自体の喪失に対する別サービスへの自動複製ではない。必要な独立保管はCSV/入力原本のダウンロードとCLIのアーカイブで行える。契約容量、外部サービスの実行時間、端末メモリーが無制限になるものではない。

## Google Driveの自動反映

- 管理画面で対象フォルダURLを設定する。初期値は既存の2026春/秋フォルダ。下位フォルダを含み、CSVの日付で任意の年度を判定する。別の親フォルダを対象にする場合もコード変更は不要。
- Google側の初回接続が必要。管理画面の連携コード/manifestをApps Scriptへ設定し、ウェブアプリをデプロイ、`setup`を一度実行してGoogleの許可を完了する。
- `changes.watch`通知 → 署名検証 → 1回限りの継続トリガー → `changes.list`の未読カーソル → 対象フォルダの新規/更新CSV、の順で処理する。毎回全ファイルの一覧を取得しない。初回setupと手動での再構築時だけフォルダを走査する。
- 6日間の通知登録を12時間ごとに延長する。この延長処理はCSVを読み取らない。取り込みを終えたfile ID + modifiedTime + sizeを記録するので、既存ファイルの増分更新も検知する。既存球の書換えは自動上書きせず停止する。
- 実行時間に近づいた場合、処理済みブロックを記録して次の単発トリガーで続行する。一時的な失敗は最大5回バックオフし、問題が続く場合は管理画面へエラーを残す。通知や外部サービスの到達を保証するものではない。
- Drive側の削除を公開データの削除へ伝播させない。全削除・訂正は管理者が保存版を確認して扱う。
- HMAC、通知token/resourceId/期限、入力UTF-8、取得前後のサイズ・更新日時・フォルダ所属を検証する。接続キー、CSV、履歴、設定操作は従来の管理者認証で保護する。
- 集計ルールそのものを変更した場合はApps Scriptも更新する。年度追加・試合追加・通常のデータ増加はエンジン更新を必要としない。
